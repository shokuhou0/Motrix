# 批量命名下载（Windows 定制开发版）

基于 Motrix v2.0.0-beta.39。此源码包不是已经生成的安装包。

## 使用方式

在“新建任务”的链接输入框中粘贴，每行一个任务：

```text
xxx01,https://example.com/a.mp4
第02集,https://example.com/b.mp4
自定义名称.mkv,https://example.com/c.mp4
https://example.com/d.mp4
```

前三项分别保存为 `xxx01.mp4`、`第02集.mp4`、`自定义名称.mkv`，第四项保留原来的自动命名方式。

- 使用英文逗号。只将第一个逗号作为名称与链接的分隔符；完整链接内的逗号保持不变。
- 名称中不能含逗号，不能是路径，也不能包含 Windows 文件名非法字符或设备保留名。
- 名称没有扩展名时，仅从网址路径的末尾提取扩展名；不从查询参数推断，也不访问服务器探测。
- 无法推断扩展名时保留输入名称。下载地址本身不会解码或改写。
- 磁力链接保持原有使用方式，不支持“名称,磁力链接”。
- 存在无效行时标出行号并阻止整个表单提交，修正后再下载。
- 每行名称优先于高级选项中的文件名。混合批量中的普通链接保持自动命名。
- 重名冲突沿用 Motrix 原有处理；本修改不增加覆盖或去重规则。

## 在 GitHub Actions 构建 Windows 安装包

1. 将源码完整放入你自己的 GitHub 仓库，保留 `.github` 文件夹。不要只上传 ZIP 文件本身；Actions 必须能看到解压后的文件。
2. 源码根目录中的 `package.json` 和 `.github/workflows/batch-windows.yml` 应位于仓库根目录下。将流程文件提交到默认分支后即可手动运行。
3. 打开仓库 **Actions → Build Windows Batch Edition → Run workflow**。
4. 全部步骤通过后，在该次运行底部的 **Artifacts** 下载 `Motrix-Batch-Windows-x64`。
5. 解压后运行 `Motrix-Batch-Setup-2.0.0-beta.39-x64.exe`。

该流程使用 Windows 2025、Node.js 24、pnpm 12.4.2、Rust 1.94.1，进行校验、相关单元测试、原生组件构建、现有添加任务端到端测试、打包校验与启动测试。某一步失败将不会提供成功的安装包产物。它只生成未签名的个人开发版，不创建公开 Release，也不修改官方发布流程。
